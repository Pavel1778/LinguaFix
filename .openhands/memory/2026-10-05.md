## Boundary-Space truncation (fixed, pushed to main)
- Symptom: `руддщ` + Space -> `рhello` (first char stranded). Root cause: daemon
  deletes `len(_scancodes)` chars, but the triggering Space is ALREADY on screen,
  so the delete shifts left and leaves the word's first char. The old
  `backspace_settle_ms` race theory was a red herring; the real defect is the
  count/boundary mismatch.
- Fix (daemon.py `_process_buffer_inner`): on a Space boundary, delete ONE extra
  char (the Space) and type `converted + " "` (trailing!), then
  `_record_undo(buffer + boundary_char, current, backspace_total)` so Ctrl+Z
  restores the pre-fix screen. Only Space is retyped (layout-invariant + typable
  by every backend); Enter/Tab keep their place after the word (retyping a
  newline/tab risks dropping it).
- `injector.can_type(char, layout)` gates the retype; `replace_text` signature is
  UNCHANGED (daemon owns the decision). Fakes in tests gained `can_type` (space-only).
- Test expectations for Space-triggered fixes now assert count+1 and a trailing
  space, e.g. `[(7, "привет ", "ru")]` / `[(6, "hello ", "us")]`.

## GUI/CLI mode switch (fixed)
- `GuiState.set_mode` and `cli.cmd_mode` only wrote config.toml; a live daemon
  kept the old mode. Both now call `daemon_control.reload_config()` when
  `is_running()` (SIGHUP -> daemon.reload_config reads mode).
