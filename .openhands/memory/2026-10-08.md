## Env quirk (cost ~30 min)
- The shell session exports `LD_LIBRARY_PATH=/usr/lib/aarch64-linux-gnu:/usr/lib:/usr/lib/x86_64-linux-gnu:`
  — the **aarch64 path first**. This makes `/usr/local/bin/python3.13` segfault
  on `import ctypes` (libffi). **`unset LD_LIBRARY_PATH LD_LIBRARY_PATH_ORIG`**
  before running pytest; otherwise the whole suite dies at import. `/usr/bin/python3`
  happened to survive; the venv python did not.

## Layero auto-deploy root cause (session 3, commits e33ba74 / 3f1e2ea)
- **The user is right: Layero auto-deploys from the connected GitHub repo — no secret.** Corrected the earlier wrong "needs LAYERO_TOKEN" note. Removed the token-based `deploy-layero.yml`.
- **Root cause found with `npx layero@latest deploy --dry-run` (no login needed):** from the **repo root** Layero reported *"This folder has no app of its own; the app is site (astro)"* — the Astro app lives in `site/`, not the root, so the platform build failed and the live RU site froze at **v0.2.7 (last-modified 11:16 UTC, i.e. pre-v0.2.8 commit 5013ae3 at 14:35)**. From `site/` it detects Astro fine.
- **Fix:** added a **root `layero.json`** so the repo is self-sufficient from the root: `{framework: "generic", buildCommand: "npm --prefix site ci && npm --prefix site run build", outputDirectory: "site/dist"}`. Root dry-run now resolves the build; a clean `git clone` of `main` builds `site/dist` with the new "Скачать словари" section. `site/layero.json` kept for folder-level/manual deploys.
- **Also fixed:** `site/package-lock.json` was stuck at `0.2.3` while `package.json` was `0.2.8` (version drift, easy to miss).
- **Layero CLI facts (v0.11.x):** `deploy --dry-run` needs no auth; `projects create --repo <provider>:<owner/repo>` connects a repo via the installed **Layero GitHub App** (path (a): push to a branch = preview, push to **main = production**). Only the **openhands-ai** GitHub App is installed on this repo — no Layero app, no webhooks — which is why the connected-repo rebuild did not fire. If the RU site stays stale, the user must reconnect the repo (or `npx layero@latest deploy`) in their Layero account; we hold no `LAYERO_TOKEN` here.
- **How to verify Layero quickly:** `curl -s --compressed "https://linguafix.layero.app/?cb=$(date +%s%N)" | grep -oE 'linguafix_[0-9.]+_all\.deb'` and check `last-modified` via `curl -sI`. `https://linguafix-main.layero.app` mirrors production.
