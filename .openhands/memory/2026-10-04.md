## Goal
Fix `—Ähello` truncation (typed `hello` in RU layout ‚Üí `—Ä—É–¥–¥—â`; replacement left
the leading `—Ä`) and make corrections happen at the word boundary instead of
after the 1.5 s idle pause.

## Root cause
The daemon computed Backspace count from the character buffer and typed the
replacement in one batch. Under fast typing the character buffer drifted from
the screen, and Chromium/Electron apply Backspace asynchronously, so the
replacement raced the deletion.

## Fix (commit 4ed6854)
- `daemon.py`: buffer stores characters **and** evdev codes (`_scancodes`);
  `_handle_event` appends a code per printable key, `_handle_backspace` pops
  both. `_process_buffer_inner` passes `len(self._scancodes)` as the count.
- New constants `_ENTER_KEYS`, `_TAB_KEYS`, `_SHIFT_KEYS`, `_WORD_BREAKERS`,
  `_NAV_KEYS`, `_INTERNAL_SEPARATOR_RE = re.compile(r"\w[.@/\\:_-]\w")`.
- Boundary handling: Space/Enter flush immediately (config-gated); disabled
  boundary resets buffer without analysing; nav keys reset; Tab opt-in.
- `injector.py`: `replace_text(backspace_count, new, layout)`; `_uinput_batch`
  writes backspaces ‚Üí `syn` ‚Üí optional sleep(`backspace_settle_ms`) ‚Üí text ‚Üí
  `syn`.
- `config.py`: `analysis_timeout` default 0.8; new `on_space`/`on_enter`/
  `on_tab`/`on_punctuation`/`punctuation_chars`/`backspace_settle_ms` with
  validation.
- `cli.py`: `replace_text(len(text), ...)`.

## Session 2 — false positives, GUI daemon control, undo

### Bug #1 false positives (guards)
Added `plausibility_check`, `structural_boundaries`, `identifier_guard`
(+ `plausibility_floor`, `max_consecutive_consonants`, `min_vowel_ratio`) to
`Config`; `detector._should_guard` runs in `target_layout` after the user-dict
override. Empirical calibration against bundled en/ru corpora: thresholds must
let `ghbdtn`/`руддщ`/`нот` pass but reject `сb cj,jq?ye;yjn/g/`. `should_fix`
uses structure-only guard (no plausibility) so it stays a superset of
`target_layout`. `tests/test_false_positives.py` (32 tests) pins must-fix,
must-not-fix, and guard-disable behavior. Privacy audit updated for the new
Config keys / detector kwargs.

### GUI daemon control (flaky toggle root cause)
Deleted `gui/systemd_bridge.py` + its test; added `src/linguafix/daemon_control.py`
(29 tests). Key insight: a daemon started by `linguafix start` (not systemd) was
invisible to the GUI because the bridge only knew `systemctl`. `daemon_control`
reads the `flock` PID lock every daemon writes, so both launch paths work.
`stop` = systemctl stop (if active) then SIGTERM→SIGKILL; `reload_config` =
SIGHUP; `undo_last_fix` = SIGUSR1 (daemon already had a SIGUSR1 undo handler).
`spawn_detached` prefers the installed launcher for the `.deb` PYTHONPATH.
HomePage toggle now polls `is_active()` (12×150ms) before refresh instead of
trusting the start/stop return value. Added an undo button to the home page.

### Gotchas
- `systemctl --user` in this container: prints a bus error but returns 0 with
  empty stdout, so `systemd_active()` correctly reports False.
- ruff's default isort splits `from x import a as b, c as d` into one import per
  name; added `combine-as-imports = true` to keep the daemon_control alias block
  readable.
