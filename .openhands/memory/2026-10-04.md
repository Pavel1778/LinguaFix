## Goal
Fix `рhello` truncation (typed `hello` in RU layout → `руддщ`; replacement left
the leading `р`) and make corrections happen at the word boundary instead of
after the 1.5 s idle pause.

## Root cause
The daemon computed Backspace count from the character buffer and typed the
replacement in one batch. Under fast typing the character buffer drifted from
the screen, and Chromium/Electron apply Backspace asynchronously, so the
replacement raced the deletion.

## Fix (commit 4ed6854)
- `daemon.py`: buffer stores characters **and** evdev codes (`_scancodes`);
  `_handle_event` appends a code per printable key, `_handle_backspace` pops
  both. `_process_buffer_inner` passes `len(self._scancodes)` as the count.
- New constants `_ENTER_KEYS`, `_TAB_KEYS`, `_SHIFT_KEYS`, `_WORD_BREAKERS`,
  `_NAV_KEYS`, `_INTERNAL_SEPARATOR_RE = re.compile(r"\w[.@/\\:_-]\w")`.
- Boundary handling: Space/Enter flush immediately (config-gated); disabled
  boundary resets buffer without analysing; nav keys reset; Tab opt-in.
- `injector.py`: `replace_text(backspace_count, new, layout)`; `_uinput_batch`
  writes backspaces → `syn` → optional sleep(`backspace_settle_ms`) → text →
  `syn`.
- `config.py`: `analysis_timeout` default 0.8; new `on_space`/`on_enter`/
  `on_tab`/`on_punctuation`/`punctuation_chars`/`backspace_settle_ms` with
  validation.
- `cli.py`: `replace_text(len(text), ...)`.
